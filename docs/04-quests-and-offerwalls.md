# 퀘스트와 오퍼월

## 오퍼월이란 무엇인가

오퍼월은 사용자가 여러 보상형 활동을 골라 참여할 수 있는 목록 또는 화면이다. 활동에는
앱 설치와 실행, 특정 조건 달성, 광고 참여, 설문 등 다양한 형태가 있다. AppTech에서는
사용자에게 이해하기 쉬운 이름으로 여러 적립소를 제공한다.

## 사용자에게 보이는 적립소 예시

| 사용자 표시명 | 연결되는 제공사 계열 | 설명 |
| --- | --- | --- |
| 급속 별 캐기 | ayeT | 앱 설치·참여형 캠페인 등을 제공하는 적립소 |
| 스타 부스트 | Oraclink/OracleX | 과거 `돈 버는 미션`으로 불리던 영역 |
| 스타 적립소 | Adison | 참여 가능한 캠페인을 제공하는 적립소 |
| 오퍼마루 | Offermaru | 별도 Web 기반 오퍼월 |

표시명과 제공사는 운영 중 변경되거나 추가될 수 있다. 사용자 문구와 내부 제공사 키를
섞지 않는 것이 중요하다.

## 일반 참여 흐름

1. 사용자가 홈 또는 퀘스트 화면에서 적립소를 선택한다.
2. Hub가 현재 사용 가능 여부와 실행 방법을 결정한다.
3. 앱은 WebView, 외부 화면 또는 내장 SDK로 적립소를 연다.
4. 사용자가 캠페인 조건과 보상을 확인하고 참여한다.
5. 제공사가 완료 결과를 Hub에 전달한다.
6. Hub가 사용자, 서명, 중복과 보상 값을 확인한다.
7. 정상 결과이면 Star 거래를 만들고 앱은 Hub 지갑을 다시 조회한다.

## 책임 구분

| 주체 | 책임 |
| --- | --- |
| 사용자 | 참여 전 조건, 보상, 기간과 유의사항 확인 |
| AppTech 앱 | 사용자를 올바른 적립소로 연결하고 완료 후 Hub 잔액 갱신 |
| AppBack Hub | 사용자 문맥 생성, 완료 통지 검증, 중복 방지, 최종 Star 반영 |
| 제공사 | 캠페인 목록과 참여 화면, 완료 조건 판정, 공식 문의 경로 제공 |

AppTech가 제휴사의 완료 조건을 임의로 다시 판정하거나, 제휴사 화면의 숫자를 바로 Star로
바꾸지 않는다.

## 캠페인 미지급 문의

미지급 문의는 다음 순서로 처리한다.

1. 참여한 캠페인 화면의 개별 고객지원 또는 제공사 문의 기능에서 완료 판정을 확인한다.
2. 제공사가 아직 완료로 판정하지 않았다면 해당 제공사의 안내를 따른다.
3. 제공사에서 지급 완료로 확인됐지만 AppTech Star에 반영되지 않은 경우 Hub 고객지원에
   문의한다.

AppTech 고객지원은 제공사 대신 캠페인 완료를 승인한다고 약속하지 않는다. 또한 근거 없이
공통 제공사 문의 URL을 추정하지 않고, 캠페인이 제공한 공식 경로를 사용한다.

## 개인정보와 추적 정보

퀘스트 실행에는 사용자와 활동 결과를 연결하기 위한 식별 정보가 필요할 수 있다. Hub는
앱이 임의 사용자 ID를 전달해 보상을 바꾸지 못하도록 로그인 계정을 기준으로 처리한다.
광고 ID나 개인별 실행 정보는 공용 URL이나 문서에 보관하지 않으며, 비밀 키는 앱과 사용자
응답에 노출하지 않는다.

VPN, 광고 차단, 광고 ID 제한과 같은 환경은 일부 캠페인의 접속이나 추적을 방해할 수 있다.
이 경우 사용자는 고객지원 Q&A의 기기 환경 안내를 먼저 확인한다.

## 서비스 원칙

- 제공사 하나의 장애가 앱 전체 사용을 막지 않아야 한다.
- 사용할 수 없는 적립소는 이유를 안내하거나 진입을 제한한다.
- 이미 시작한 캠페인의 식별값과 실행 경로를 임의로 바꾸지 않는다.
- 모니터링 실패만으로 정상 사용자의 퀘스트 실행을 조용히 변경하지 않는다.
- 보상 결과는 지갑 거래와 제공사 완료 기록을 연결해 추적할 수 있어야 한다.
